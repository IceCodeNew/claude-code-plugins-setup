Write a plan for: $ARGUMENTS

Read the relevant code, tests, and constraints first. State the decision, the
options considered, and the tradeoff. Then give an ordered plan with acceptance
criteria, files or areas to touch, verification for each step, risks, and what you
would deliberately not build. Keep it executable by a separate implementation
session; do not write the implementation now.

If a requirement is genuinely ambiguous, ask one focused question; otherwise state
the assumption and proceed.
