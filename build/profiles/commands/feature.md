Implement this feature: $ARGUMENTS

Start by reading the relevant code, conventions, and tests. Write a short plan
with acceptance criteria and the files you expect to touch. If a design choice is
genuinely ambiguous, ask one focused question; otherwise make the routine call and
keep going.

Implement in small, coherent steps. Add or update tests that assert user-visible
behavior. Run the narrowest test first, then the broader suite if the change
warrants it. Review your own diff for unrelated edits, error paths, and missing
documentation. Report: what changed, why, files, verification, and remaining
risk.
