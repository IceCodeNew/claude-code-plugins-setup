Design or polish the UI in $ARGUMENTS.

Read the existing components, design tokens, and layout conventions first. Decide
the single visual idea that makes this screen distinct; do not stack unrelated
effects. Check hierarchy, spacing, typography, color contrast, empty and loading
states, and the narrow-screen layout.

Make the smallest coherent change and keep the existing design system. Verify in a
real browser or the repository's screenshot test; do not claim visual quality from
source code alone. Report: the design decision, files, and how you verified it.
