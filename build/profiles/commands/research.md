Research: $ARGUMENTS

Use GitHub code search / `gh` for repositories, `firecrawl` or `read` for web and
docs, and context7 for library documentation. State the repository, branch, tag, or
commit you read; do not mix versions. For a multi-repository question, map the
repositories first, then read the specific files.

Cite file paths, line numbers, and URLs. Separate source evidence from inference.
If a fetch or search fails, report it instead of guessing. Do not edit repository
code; produce a concise brief with the answer and the sources.
